# Flexim UI — правила и частые ошибки (живой свод)

Этот файл — **обязательное чтение перед версткой/правкой UI**. Сюда попадает
каждая найденная ошибка как правило с причиной, чтобы она **не повторялась**.
Если правишь компонент и понимаешь «вот так делать нельзя / надо вот так» —
добавь сюда строку.

Формат записи: **Правило** — коротко что делать. **Почему** — причина/контекст.

---

## Базовые правила (всегда)

- **Бери компонент из каталога `prod-mockups/components.html` и копируй разметку 1:1.**
  Почему: каждый «свой» вариант расходится с библиотекой и плодит баги.
- **Только токены `var(--*)` из `tokens.css`.** Никаких `#hex`, `rgb()`,
  inline `style="color/font-size"`. Почему: единый бренд и быстрая перекраска прода.
- **Иконки только через `<span data-flexim-icon="имя" data-size="24">`** + `fleximIcons.renderAll()`.
  Почему: единый набор; произвольные SVG/эмодзи выпадают из системы.
- **Стек неизменен: Bootstrap 4.0.0 + jQuery 3.5.1.** Порядок стилей:
  bootstrap → tokens.css → _bootstrap-flexim-overrides.css.
- **Эталон — Figma UI Kit.** Чего нет — сверь с Figma, собери в том же стиле,
  добавь в каталог (а не делай одноразовый локальный вариант).
- **Тег по действию, не по виду: переход на URL = ссылка `<a href>`, действие на странице = `<button>`.**
  Правило одинаково работает для **всех «кликабельных» компонентов** — Button
  (`.btn`, любого варианта), табов header-menu (`.flexim-header-menu__item`),
  пунктов меню и т.д. Стиль и зона клика — на CSS-классе, тег визуально
  не отличается.
  - **Переход на адрес** (другая страница, фильтр через `?status=…`, ссылка на
    создание) → `<a href="…" class="…">`. Пример: «Новый расчёт» = `<a href="create.php" class="btn btn-dark">`.
  - **Действие на текущей странице** (модалка, сабмит, JS-обработчик,
    разворот блока) → `<button type="button" class="…">`.
  - **Конкретно для табов header-menu:** «Отгружено / В работе / Расчёты…» —
    это `<a class="flexim-header-menu__item">`, не `<button>`.
  - Почему: `<a>` даёт Ctrl/Cmd+клик (новая вкладка), «копировать адрес», честный
    URL под закладку и доступность из коробки — у `<button onclick>` этого нет.
    `<button>` правильнее для in-page действий: не оставляет «#» в адресе, не
    предлагает «открыть в новой вкладке» там, где это бессмыслица.
  - При переходе на React логика **сохраняется**: компонент `<Button>` смотрит
    проп `href` — если есть, рендерит `<a>` (или `<Link>` роутера), иначе `<button>`.
    То есть «один компонент, тег по семантике» — переносится один-в-один.

## Никакой самодельной вёрстки контента — только компоненты системы

- **Любой контент собирается из компонентов библиотеки** (Button, Input, Select,
  Table, List, Card, Tabs, Chips, Status-banner, header/header-h4, nav-rail и т.д.).
  Нельзя вводить свои классы вроде `.calc-title`, `.calc-cost-num` под текст/цифры —
  это «отсебятина мимо системы». Цифры «ключ→значение» = компонент **List**;
  заголовки = page-header / header-h4; поля = Input. Почему: единый вид и поведение,
  иначе экран расходится с библиотекой.
- **Единственное допустимое page-level CSS — структурный каркас** (flex-раскладка
  shell: рейка + main + topbar + content, ширины колонок). Это не «компонент», а
  скелет страницы. Всё остальное — из системы.
- **Общий каркас живёт в `_bootstrap-flexim-overrides.css`, а не дублируется в
  каждом HTML.** Классы `.app-shell`, `.app-main`, `.app-topbar`,
  `.app-content`, `.app-topbar .flexim-header-menu`, `.app-topbar__right` — это
  единый каркас списочных экранов и карточек. Они **уже в overrides**, секция
  «APP SHELL». В `<style>` экрана — **только специфика этого экрана** (например,
  у order-card свой `.app-content { padding: 0 }` + `.calc-tabs`, `.calc-body`).
  Почему: иначе один экран правишь, другой нет — расходятся.
- **Уникальные одноразовые каркасы** (например, `.auth-shell` / `.auth-hero` /
  `.auth-form` у логина) — остаются в `<style>` страницы, потому что больше
  никем не используются и в overrides им не место.
- **Если что-то приходится верстать с нуля — обязательно сообщи Маше до того,
  как начнёшь.** Молча сочинять свой компонент/класс/структуру нельзя. Сообщение
  должно содержать: что именно нужно сверстать, почему не подходит то, что уже
  есть в каталоге, и предложение/вопрос (добавить новый компонент в ДС?
  использовать существующий с модификатором?). Жди явного «да» от Маши, потом
  верстай. Почему: это страховка от тихого расхождения с системой.

## Названия и состав разделов (parity с Figma)

- Раздел поля называется **Input** (не «Forms»), селект — **Select** (не «Selects»).
  Почему: каталог должен совпадать с китом по названиям 1:1.
- **Notificator** — отдельный раздел (`#flexim-notificator`, в меню между
  Navigation и Pagination). Почему: в Figma это самостоятельный компонент, не
  часть Chips.
- **Chips → chip-status**: 15 цветов (success/warning/error/info/black/blue/
  purple/violet/pink/orange/yellow/terracot/brick/shrek/green) + кликабельный
  вариант `.flexim-chip-status--clickable` со стрелкой `arrow-right` 16px.
  Почему: каталог показывает всю палитру и оба варианта (со стрелкой / без).
  Насыщенный фон (20%, hover/выбран) статично — модификатор
  `.flexim-chip-status--strong` (та же заливка, что и `:hover`).
- **Tooltip-label** (`.flexim-tooltip-label`, Figma 7839:132372) — статичная
  закрываемая плашка-метка. **Не путать** с `.flexim-tooltip` (popup со
  стрелкой и позициями). У label нет хвостика, нет позиций — это inline-метка
  или уведомление. Варианты: `--light` (белый фон) и `--dark` (фон
  `--background-dark`). Опциональный крестик `.flexim-tooltip-label__close`
  (иконка `x-small` 16px в кнопке 24×24). Клик по крестику удаляет плашку.
- **Новый токен `--background-dark: #6F6E75`** в группе background — тёмный
  серый для тёмных поверхностей (используется в `.flexim-tooltip-label--dark`).
  В Figma — `background/dark`.

## Контролы (checkbox / radio / switch)

- **Кликается весь компонент, а не только кружок/трек.** Нативный `<input>` —
  replaced-элемент: `inset:0` его НЕ растягивает, нужны явные `width:100%; height:100%`.
  Почему: иначе зона клика — только маленький нативный квадрат.
- **Disabled должен перебивать checked и Bootstrap.** У Bootstrap 4 есть правило
  `.custom-* .custom-control-input:disabled:checked ~ label::before` (специфичность
  0,5,1) с синим фоном. Наши disabled-правила обязаны быть `:disabled:checked`
  (0,5,1) и идти ПОЗЖЕ, иначе выключенный «включённый» контрол остаётся розовым/синим.
- **Тоггл в таблице центрируется по вертикали:** у `.flexim-table__cell .custom-control`
  задаём `display:flex; align-items:center; height:24px`, иначе уезжает вниз.

## Поля, селекты, поиск

- **Нативный `<select>` нельзя стилизовать в открытом виде** — ОС рисует свой
  список. Для дизайна используем кастомный `.flexim-select` (триггер + `.flexim-dropdown`).
- **Select (Figma 4317:85067) = оболочка Input + шеврон.** Триггер — это
  `.flexim-input` с классом `.flexim-select__trigger`; в конце слот
  `.flexim-select__chevron` (`arrow-down-small`, серый, поворот 180° + primary при
  open). Все слоты и состояния берём у Input: иконка · контент (`__text` /
  `__text--placeholder` / чипы) · `__clear` · `__unit`. Состояния — модификаторы
  Input: `--hover`, `--focus` (= open, бренд-рамка), `--error` (+ строка
  `.flexim-input-field__hint`), `--disabled` (обёртка `.flexim-select.is-disabled`),
  `--readonly` (= borderless). Не делать селекту отдельную рамку/высоту — только
  через Input, иначе разъедется.
- **Мультивыбор** (`.flexim-select--multi`): выбранные значения — `chip-tag--s` с
  крестиком внутри `__content`; клик по пункту тогглит активность и пересобирает
  чипы, меню не закрывается; удаление чипа снимает активность у пункта.
- **Input и Select — две разметки: витрина vs рабочая форма.**
  - **Витрина** (матрица состояний в каталоге, для дизайн-сверки с Figma): внутри
    `.flexim-input__content` лежит `<span class="flexim-input__text">`, состояния
    задаются модификаторами `--hover/--focus/--error/--disabled/--readonly`.
    **В прод не использовать — печатать нельзя.**
  - **Рабочая форма** (логин, фильтры, любые поля): внутри `.flexim-input__content`
    кладём `<input class="flexim-input__field" type="..." placeholder="...">`.
    Focus-рамка приходит автоматически через `:focus-within` на шелле, ручной
    `--focus` ставить не нужно. Образец — секция «Рабочий пример» в `#forms`.
  - **Action-slot** (`.flexim-input__action`) — универсальная кнопка-иконка
    справа от поля: eye toggle для пароля, copy, paste и т.п. Семантика отличается
    от `.flexim-input__clear` (та — конкретно «крестик очистки значения»):
    `__clear` — для ✕, `__action` — для всего остального. Стилизация идентичная
    (бренд-розовый цвет, hover на bright, серый в disabled). Образец — группа
    «Action-slot» в `#forms`. Не путать с `__clear` — это две разные роли.
  - **Select для формы**: внутри `.flexim-select` рядом с триггером/меню кладём
    `<input type="hidden" class="flexim-select__value-input" name="..." value="...">`.
    JS (`fleximUpdateSelectHidden`) сам пишет в него выбранное значение —
    одно для single, через запятую для multi. Без hidden значение в форму не уйдёт.
- **Filter-dropdown для формы.** В `.flexim-filter-dd` добавляем
  `<input type="hidden" class="flexim-filter-dd__value-input" name="...">`. JS клика
  по `.flexim-filter-dd__menu .flexim-dropdown__item` пишет в него label выбранного
  пункта. Без hidden — фильтр в submit не уйдёт (AJAX-фильтрация — отдельно).
- **Segment control для формы.** В `.flexim-segment` добавляем
  `<input type="hidden" class="flexim-segment__value-input" name="..." value="...">`.
  Новый JS-обработчик клика по `.flexim-segment__item:not(:disabled)` тогглит
  `--active` и пишет в hidden. Без него active-state — только визуальный.
- **Slider — визуализация, не контрол.** `.flexim-slider--static` — статичное
  превью (для дизайн-сверки). Для рабочего диапазона добавляем
  `<input type="hidden" class="flexim-slider__value-input" name="...">`; драг
  thumb и обновление значения — задача программиста (или будущей JS-обёртки).
- **Date picker — визуализация, не контрол.** `.flexim-datepicker` показывает
  календарь без интерактива (клики по `.flexim-datepicker__day` не обрабатываются).
  Для рабочей формы добавляем пару `<input type="hidden" class="flexim-datepicker__value-input"
  name="date_from/date_to" value="YYYY-MM-DD">`. Клики по дням / выбор пресета —
  программист либо использует native `<input type="date">` параллельно, либо
  пишет свой обработчик и обновляет hidden inputs.
- **Dropdown — пункты с ведущими иконками** (Figma 4317:91189): иконка слева
  (24px, бренд-розовая), текст; hover — фон `primary-50`; **disabled — иконка и
  текст серые** (`text-disabled`, не розовые). Активный пункт — `--active`.
- **Card «катушка»** (`.flexim-card-roll`, Figma 4385:53813): композит из наших
  компонентов — грип (6 точек) + название/подзаголовок + `chip-status` справа,
  ниже строка из инпутов (`flexim-input` + `__unit`, по 150px) и ghost-кнопки
  `btn-outline-primary` с иконкой `print`. Не верстать заново — брать из каталога.
- **У кастомных компонентов hover нужно прописывать явно.** У `.form-control`
  ховер есть, а у новых (select-триггер, search-поле) — нет, пока не добавишь
  `:hover { box-shadow: var(--shadow-s); }`.
- **`<label>` имеет `margin-bottom: .5rem` от Bootstrap.** Если используешь
  `.flexim-input-field__label` на теге `<label>` (правильно — для связи `for`/`id`,
  доступность), Bootstrap добавит снизу 8px и зазор до инпута станет 12px вместо
  ожидаемых 4px. Класс сам сбрасывает margin — но если делаешь любую новую
  лейбл-обёртку, помни про этот сброс.
- **Конвенция hover (куда добавлять):** любой кликабельный элемент должен иметь
  hover. Поля/триггеры/поиск — тень `--shadow-s`; иконки-экшены и крестики
  очистки (table cell-action, accordion action, input clear) — цвет
  `--primary-light`; кликабельные заголовки (accordion) — тинт `--primary-main`;
  пункты списков/меню/дропдаунов — фон `--primary-50` или `--other-table-hover`.
- **Выбранный/активный элемент не реагирует на hover.** В hover-правила добавляй
  `:not(.…--active)` (segment, tabs-underline и т.п.), либо отдельное правило
  `--active:hover`, которое держит активный вид (как у tabs-pill, menu-item).
  Почему: hover на уже выбранном элементе сбивает с толку.

## Фильтры (Figma 4398-81740)

- **Невыбранный фильтр — пилюля-дропдаун** `.flexim-filter`: прозрачный фон,
  h-32, padding 4×12, radius 8, текст 14/20 **bold primary-main** + шеврон
  (`arrow-down-small`). Hover — фон primary-50.
- **Выбранное значение фильтра — это chip-tag** (`.flexim-chip-tag--s`): белая
  пилюля + тень + тёмный текст + крестик `x-small`. Не делать отдельный компонент.
- Строка фильтров живёт в `.flexim-header__actions` (gap 16) справа от заголовка;
  справа — «Новый расчёт» (primary) + kebab (`btn-outline-primary btn-icon`).
- **Между строкой заголовка/фильтров и таблицей — отступ** (`.flexim-header`
  margin-bottom ≈ size-l). Почему: фильтры не должны «прилипать» к таблице.
- **Фильтр-кнопка открывает дропдаун с полем поиска внутри** (`.flexim-filter-dd`):
  триггер = `.flexim-filter` (пилюля), поповер = `.flexim-dropdown` с
  `.flexim-filter-dd__search` (поле `.flexim-search__field`) сверху + список
  `.flexim-dropdown__item`. Для свободного ввода — поле + footer «Применить/Сбросить».
  Так сохраняем вид пилюли (Figma) и поиск по значениям (реальное приложение).
  Клик по полю поиска не закрывает дропдаун (stopPropagation), выбор пункта — закрывает.

## Табы

- **`.flexim-tabs` — `inline-flex`** (по размеру содержимого). Поэтому элемент
  СРАЗУ после блока табов (например, кнопка «К списку») прилипает справа на той
  же строке. Решение: оборачивать такой элемент в блок (`<div>…</div>`), чтобы он
  встал на свою строку. Менять сами табы на `display:flex` глобально нельзя —
  сломается pill-вариант (фон растянется на всю ширину).
- **Детальная страница: панель под-табов — полноширинная и прижата к хэдеру.**
  Под-табы (Расчёт / Тех. карта / Результаты) выносить из колонки в
  полноширинную панель в начале `.app-content` (у `.app-content` `padding: 0`
  → 0px до хэдера). Серую линию тянуть **до края экрана**: на самой панели табов
  поставить `display: flex` + горизонтальный `padding` (border-bottom охватит всю
  ширину, а табы инсетятся паддингом). Контент колонок — ниже панели, в обёртке
  с отступами (напр. `.calc-body { padding: var(--size-xl) }`). Правую плашку
  (карточку «Расчёт») это автоматически опускает под линию. Образец —
  `prod-mockups/02-order-card.html`.

## Кнопки и иконки

- **Иконка+текст в кнопке центрируются, если svg = `display:block`.** Inline-svg
  садится на baseline и уезжает вверх. Правило: `.btn [data-flexim-icon]{display:inline-flex}` +
  `.btn svg{display:block}`.

## Модалки

- **Футер модалки — кнопки СЛЕВА** (`justify-content: flex-start`), главное/
  деструктивное действие первым (напр. «Удалить»), затем «Отмена». Расстояние
  между кнопками ровно 16px. Bootstrap `.modal-footer > :not(:first-child)`
  добавляет свой margin — гасить через `.modal-footer.flexim-modal__footer > * { margin:0 !important }`.
- **Любая Bootstrap-модалка (`.modal`) должна нести классы системы**
  `.flexim-modal__header/__title/__body/__footer`, иначе футер по умолчанию
  выравнивается вправо (Bootstrap) — не как в Figma. Закрытие — иконка `x` (24).

## Каркас страницы и навигация

- **Верхняя шапка (header menu) — вплотную к краям, без отступов вокруг.**
  В каркасе: `.app-topbar { padding: 0 }` и `.flexim-header-menu { border-radius: 0 }`
  (в каталоге компонент показан как скруглённая карточка — это только для витрины).
  Почему: на реальной странице шапка — сплошная панель от края до края.
- **Левая рейка: hover пункта + подсказка с названием раздела.** Hover —
  `background: var(--other-table-hover)` (active остаётся primary-50 + бордер).
  Подсказка — `::after { content: attr(aria-label) }` справа, в стиле Tooltip.
  Почему: рейка icon-only, без подписи пользователь не понимает раздел.

## Содержимое экранов — из РЕАЛЬНОГО приложения, не из Figma

- **Наполнение экранов (разделы навигации, названия, данные, структура) берём
  из реального приложения** (тест-стенд `pr-diz-test.ru`), а НЕ из Figma.
  Figma UI Kit — это про **компоненты** (как выглядит кнопка/таблица/поле), а
  состав экранов и разделов в проде другой. Почему: иначе соберём красивый, но
  не тот экран.

### Экран «Заказы» (`/calculation/`) — реальная структура

- **Верхний бар:** слева табы-воронка `Отгружено · Ждёт отгрузки · Производят ·
  В работе · Расчёты · Черновики · Корзина`; справа — иконка поиска + user-чип.
- **Заголовок:** H1 = название активного таба (напр. «Отгружено») + большое
  число-счётчик рядом (напр. 5995, серое).
- **Фильтры** (строка справа от заголовка): `Шт/кг`, `Тип работы`, `Менеджер`,
  `Заказчик`, `Наименование` + кнопка **«+ Новый расчёт»** (primary).
- **Колонки таблицы:** ID · Дата расчёта · Заказчик (ссылка) · Имя заказа ·
  Объём (кг) · Тип работы · Менеджер · Статус · ⋮(kebab). Все сортируемые.
- **Ячейка статуса:** цветная точка + название + подстрока прогресса
  (например «Отгружено / 100,85 из 90 кг»).
- **Пагинация: 50 строк на страницу.** Проверено в проде: «Отгружено 5995» → 120
  страниц (5995 ÷ 50 ≈ 120, последняя неполная). Компонент `.flexim-pagination`.
  Шаблон номеров на первой странице: `1 2 3 4 5 6 7 … 120 »` — первые 7 страниц,
  многоточие (`--ellipsis`), всегда последняя страница, стрелка «дальше». В
  середине списка появляется и стрелка «назад» (`«`). Текущая страница —
  `--active` (подсвеченная ячейка, тёмный жирный текст). Вся пагинация — **ячейки
  в общей рамке с разделителями** (как в проде): контейнер с рамкой и radius,
  внутри ячейки делятся `border-left`, без теней и зазоров. Почему: расхождение
  по числу строк ломает соответствие реальному списку.
- **Пагинация показывается только если страниц больше одной.** Если всего записей
  ≤ 50 (умещаются на одну страницу) — блок пагинации **не выводим вообще**. Почему:
  при < 50 строках пагинация бессмысленна и мусорит интерфейс.
- **Колонка ID не переносится.** На таблицу вешаем `.flexim-table--id-first` —
  первая колонка (ID/номер заказа) получает `width:1%` + `white-space:nowrap`,
  т.е. сжимается по содержимому и всегда показывает номер целиком (не «216-/545»).
- **Колонка «Имя заказа» ужата.** Модификатор `.flexim-table--name-clamp` ставит
  4-й колонке (название) `max-width:260px` + перенос, чтобы длинные названия не
  растягивали таблицу и оставалось место остальным колонкам.
- **Таблица списка тянется на всю высоту экрана, скролл — внутри.** Обёртка
  `.flexim-table-wrap--page-fill` (flex:1, min-height:0) + внутренний
  `.flexim-table__viewport` (own scroll, полоса в правом жёлобе) + шапка
  `--sticky-head`; пагинация (`tfoot`) остаётся снизу вне скролла. Требование:
  родитель — flex-column с заданной высотой (`.app-content` → `min-height:0`,
  `display:flex; flex-direction:column`). При 50 строках/стр таблица почти всегда
  выше вьюпорта, поэтому full-height + внутренний скролл обязательны.
- **Чего НЕТ** (а я ошибочно добавлял): колонки чекбокса, свитча «Активный»,
  кнопки «Открыть» в строке, kebab-кнопки рядом с «Новый расчёт». В проде их нет —
  не выдумывать.
- Клик по **заказчику** открывает правую панель (Sidebar) с карточкой клиента;
  заказ открывается через ⋮ (детали расчёта). Не путать.

### Карточка заказа (`/calculation/details.php`) — реальная структура

- Под-табы слева сверху: **Расчёт · Тех. карта · Результаты**; кнопка «← К списку».
- H1 = имя заказа + подзаголовок «№216-545 от 05.05.2026»; статус-баннер
  («Отгружено 100,85 из 90 кг»).
- **Левая колонка** (сводка, без рамки): секции «О заказе», «Характеристики»,
  «Пленка» (label/value), кнопка «Пересчитать».
- **Правая колонка** — карточка «Расчёт»: наценки (тираж %/₽, ПФ) + курсы €/$,
  блок «Стоимость» в 3 колонки (Себестоимость / Отгрузочная стоимость / Прибыль,
  с ПФ и итоговой прибылью), блок «Материалы» в 3 колонки (Основная пленка /
  Ламинация 1 / Ламинация 2), ссылка «Показать расходы», иконки экспорт/печать.

## Экран входа (Login)

- **Каркас Login = структурный page-level CSS, а не компонент.** Двухколоночный
  shell `.auth-shell` (hero слева + форма справа, на мобилке стек) — это скелет
  страницы, не компонент DS. Контент внутри собирается из компонентов библиотеки;
  типографика — классы `.t-*` из `tokens.css` (`.t-h1` для бренд-имени, `.t-h2-r`
  для заголовка «Вход»). Поля — `.flexim-input` с разметкой «Рабочий пример» из
  секции `#forms` (внутри `__content` — `<input class="flexim-input__field">`).
  Эталон — `prod-mockups/03-login.html`.
- **Каркас одинаковый для всех вариантов входа** (`03-login.html` — пароль,
  `04-login-users.html` — список юзеров, `04-login-pattern.html` — ключ).
  Уже три экрана — пора выносить `.auth-shell` / `.auth-hero` / `.auth-form`
  в overrides как `.flexim-auth-*`, а в page-level каждого файла оставлять
  только специфику варианта. Почему: сейчас каркас дублируется в трёх
  файлах, любая правка (отступы, mobile-точка) разъезжается.
- **Карточка прижата к верху + одинаковый top-отступ.** `.auth-form` —
  `align-items: flex-start; padding: calc(var(--size-xxxl) * 4) ...`
  (160px top, кратно 8). Почему: при `align-items: center` карточки разной
  высоты (логин/пароль 320px vs список юзеров 480px) дают разный верхний
  пробел и визуально не согласованы. Отступ кратен 8 — общее правило сетки.
- **Логотип Flexim в hero — компонент `.flexim-logo__mark`** из каталога
  (секция `#flexim-logo`). По дефолту 32×32, в Figma макете логина — 60×60;
  локально переопределяем размер под этот экран (`.auth-hero .flexim-logo__mark`).
  Бренд-имя «Принт-Дизайн» — типографика `.t-h1` (`tokens.css`); цвет
  (`--text-contrast`) и `white-space: nowrap` — локально как часть каркаса.
- **Action-кнопка «глаз» для пароля — пока в слоте `.flexim-input__clear`.**
  Это AD-HOC переиспользование универсального action-slot (24×24, transparent,
  hover `primary-light`): иконка задаётся через `data-flexim-icon="eye-closed"`/
  `eye-open` (реестр, категория form). jQuery-тогглер переключает у `<input>`
  атрибут `type`, у кнопки — `data-flexim-icon`/`aria-pressed`/`aria-label`,
  и зовёт `fleximIcons.renderAll()`. Когда добавим в DS отдельный слот
  `__action` / `__toggle` — переименовать.
